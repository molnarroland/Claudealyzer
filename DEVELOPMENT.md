# Development

This document covers building, testing and packaging Claudealyzer. For what the app does, see the
[README](README.md).

## Stack

| Layer | Technology |
|---|---|
| Backend | Go 1.26, [Wails v3](https://v3.wails.io) (`v3.1.0`) |
| Frontend | Angular 22, [Spartan NG](https://spartan.ng) (helm components), [Spartan Native](https://github.com/Spartan-Native/spartan-native) (desktop UI + platform skins) |
| Build runner | [Task](https://taskfile.dev) via `wails3 task` |

## Prerequisites

- **Go 1.26+**
- **Node 26** — the version is pinned in `.nvmrc`; run `nvm use`
- **Wails 3 CLI**
  ```sh
  go install github.com/wailsapp/wails/v3/cmd/wails3@v3.1.0
  wails3 doctor   # checks platform dependencies
  ```
- Platform toolchain:
  - **macOS**: Xcode Command Line Tools (`xcode-select --install`)
  - **Windows**: WebView2 runtime (bundled with Windows 11); NSIS for the installer
  - **Linux**: `gcc`, `libgtk-3-dev`, `libwebkit2gtk-4.1-dev` (or the equivalents for your distro)
- **Docker** — only for cross-compiling Linux/Windows builds from another OS

## Run in development mode

```sh
nvm use
wails3 dev
```

This starts `ng serve` on port `9245` and rebuilds the Go side on change. The frontend dependencies are
installed automatically on the first run (`npm install` in `frontend/`).

## Build

```sh
wails3 build        # production binary for the host OS → bin/claudealyzer
wails3 task run     # build and run
```

### Package

```sh
wails3 package      # host-OS package (.app / installer / AppImage …)
```

macOS variants:

| Task | Output |
|---|---|
| `wails3 task package:mac:arm64` | `bin/claudealyzer-arm64.app` (Apple Silicon) |
| `wails3 task package:mac:amd64` | `bin/claudealyzer-amd64.app` (Intel) |
| `wails3 task package:mac:universal` | `bin/claudealyzer.app` (both architectures, `lipo`) |
| `wails3 task package:mac:all` | all three |
| `wails3 task darwin:package:dmg` | styled `.dmg` |

The minimum macOS version is **12.0**. Bundles are ad-hoc signed; set up a Developer ID and use
`wails3 task darwin:sign:notarize` for a notarized release.

Linux: `wails3 task linux:create:appimage`, `linux:create:deb`, `linux:create:rpm`, `linux:create:aur`.
Windows: `wails3 task windows:create:nsis:installer`, `windows:create:msix:package`.

### Cross-compiling

Linux and Windows CGO builds from another OS run inside a Docker image. Build it once:

```sh
wails3 task setup:docker                       # image for the host architecture
wails3 task common:setup:docker ARCH=amd64     # extra image for another arch (e.g. x64 Linux on Apple Silicon)
```

Then build for a target with `GOOS` / `ARCH`:

```sh
wails3 build GOOS=windows
wails3 build GOOS=linux ARCH=amd64
wails3 build GOOS=linux ARCH=arm64
```

Cross-arch Linux images run emulated (Rosetta/QEMU) and are slower.

## Tests

```sh
go test ./...
```

Adapters are tested against small synthetic transcripts in `internal/adapters/*/testdata`.
Pricing and insight rules have their own unit tests in `internal/pricing` and `internal/insight`.

Frontend type check / production build:

```sh
cd frontend && npm run build
```

### Dev tools

```sh
go run ./cmd/czscan                       # scan all configured sources and print totals
go run ./cmd/czdump <agent> <file.jsonl>  # parse one session file and print a summary
                                          # agent: claude | codex | gemini
```

## Project layout

```
main.go                       Wails app, services, events
internal/model                agent-neutral Session / Turn / Step / Usage
internal/adapters             one adapter per agent (claude, codex, gemini) + shared turn builder
internal/pricing              versioned price table (default_pricing.json), cost calculation
internal/insight              cost rules → findings (grouped per rule)
internal/core                 sources config, summary index + cache, queries, reports, calendar
internal/services             thin Wails-bound services
cmd/czscan, cmd/czdump        dev tools (see above)
frontend/src/app/views        History, Session analysis, Cost explained, Overview, Calendar, Settings
frontend/src/app/charts       SVG charts (stacked bars, line)
frontend/bindings             generated by `wails3 generate bindings` — do not edit by hand
frontend/libs/ui              Spartan NG helm components (generated with the Spartan CLI)
build/                        platform build config, icons, installers, Taskfiles
```

After changing a Go service signature, regenerate the TypeScript bindings:

```sh
wails3 generate bindings
```

## Runtime data

| What | Where |
|---|---|
| Config (sources, billing, thresholds) | `os.UserConfigDir()/claudealyzer/config.json` |
| Edited pricing table | `os.UserConfigDir()/claudealyzer/pricing.json` |
| Summary cache | `os.UserCacheDir()/claudealyzer/index.json` |

The cache is keyed by path + size + mtime and dropped when pricing or thresholds change.
Sources are rescanned every 15 s.

## Adding an agent

1. Add the agent constant in `internal/model/model.go`.
2. Implement the `Adapter` interface (`internal/adapters/adapter.go`) in `internal/adapters/<agent>/` and
   register it with `adapters.Register`. Parse the transcript into the
   agent-neutral `Session` / `Turn` / `Step` / `Usage` model; use the shared turn builder.
3. Deduplicate usage by the agent's response id, and normalise tokens (uncached input, cache write,
   cache read, output).
4. Add detection in `internal/core/queries.go`.
5. Add synthetic test transcripts under `testdata/` and a test.
6. Add the agent's models to `internal/pricing/default_pricing.json`.

## Website and screenshots

The project website is a static page in `docs/` (`index.html`, `site.css`, `site.js`), served by GitHub Pages.
Enable it under *Settings → Pages → Deploy from a branch → `main` / `docs`*. The repository URL used by
every GitHub link on the site is set once, in `window.REPO` at the top of `docs/index.html`.

Screenshots in `docs/images/` are made from the real app running against generated demo data (a made-up
user and projects), never from real transcripts.

## Updating prices

Prices live in `internal/pricing/default_pricing.json`. Entries are **versioned by date**: add a new entry
with a `from` date instead of changing an existing one, so older sessions keep their historical price.
